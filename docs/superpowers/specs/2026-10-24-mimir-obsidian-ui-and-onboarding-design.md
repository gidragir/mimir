# Mimir: Obsidian-Style UI, Native Folder Picker & Initial Sync Onboarding

**Дата:** 2026-10-24  
**Статус:** Approved (после Builder Check)  
**Область:** `ui`, `app-desktop`, `daemon`, `core`

---

## 1. Контекст и мотивация

Текущий пользовательский интерфейс Mimir построен на стандартных компонентах Material 3 с фиолетово-синей палитрой Material You, крупными скруглениями (28 dp) и ручным текстовым вводом пути к хранилищу Obsidian. Это создает три проблемы:
1. **Эргономика**: Пользователю неудобно вводить полный абсолютный путь к папке хранилища вручную вместо вызова привычного системного диалога выбора папки.
2. **Непрозрачность первого запуска**: Если пользователь подключает существующее облачное хранилище к локальной папке (или наоборот), неочевидно, что произойдет с данными (перезапись, удаление или слияние). Пользователю требуется явное подтверждение стратегии слияния перед запуском синхронизации.
3. **Визуальная идентичность**: Интерфейс приложения для Obsidian должен органично вписываться в эстетику экосистемы Obsidian — глубокая темная тема, чистая светлая тема, компактные отступы, тонкие границы, акцентный фиолетовый цвет `#705dcf`.

## 2. Цели, не-цели и анти-цели

### Цели
- Предоставить нативный диалог выбора папки (Directory Picker) на Desktop с сохранением возможности ручного ввода/редактирования пути.
- Обеспечить кроссплатформенную чистоту KMP в модуле `ui` без жесткой связки `commonMain` с AWT/Swing.
- Внедрить в мастер первого запуска шаг анализа и подтверждения начального состояния: инспекция локальной папки и расшифрованного облачного дерева с подтверждением двустороннего слияния (`TwoWayMerge`).
- Переработать `MimirTheme` и компоненты в соответствии с дизайн-системой Obsidian с поддержкой как Dark Mode (`#1e1e1e`), так и адаптивной Light Mode (`#ffffff` / `#f6f6f6`).

### Не-цели
- Встраивание редактора Markdown или просмотрщика заметок внутрь Mimir.
- Кастомные безрамочные декорации окон (Client-Side Decorations), нарушающие работу тайлинговых композиторов (Niri, Sway).
- Изменение криптографического формата Rclone Crypt или низкоуровневого протокола синхронизации.

### Анти-цели
- Блокировка потока отрисовки Compose UI при открытии модального диалога проводника.
- Автоматический старт синхронизации в фоне до подтверждения пользователем на шаге 4 мастера.
- Деструктивная перезапись введенного пути при отмене диалога выбора папки.

## 3. Архитектурные решения и рассмотренные подходы

### Вариант 1. Инверсия зависимостей в UI + 4-й шаг мастера с инспекцией (Выбран)
- **Выбор папки**: В `ui/commonMain` создается интерфейс `PlatformFolderPicker` (`suspend fun pickDirectory(initialPath: String?): String?`). В `app-desktop` предоставляется реализация на базе AWT/Swing `JFileChooser(DIRECTORIES_ONLY)` на `Dispatchers.IO`. Передается в Compose через `LocalFolderPicker`.
- **Мастер настройки**: Порядок шагов:
  1. Выбор локальной папки (с кнопкой «Обзор…» и счетчиком обнаруженных локальных заметок из `POST /api/v1/vault`).
  2. Авторизация Google Drive.
  3. Ввод мастер-пароля шифрования.
  4. Инспекция хранилищ: запрос к демону `GET /api/v1/vault/inspect`; показ карточки с подтверждением стратегии «Двустороннее слияние с защитой от потерь».
- **Предотвращение гонки фоновой синхронизации**: При первоначальной настройке мастер держит флаг незавершенности; `DaemonRuntime` не запускает периодический `scheduler.start()`, пока на шаге 4 не нажата кнопка «Завершить настройку и синхронизировать».

### Вариант 2. Обработка начального состояния через статус демона (Отклонен)
- Демон при старте синхронизации переходит в статус `AwaitingResolution` и блокирует работу до специального API-запроса; пикер реализуется через `expect/actual`.
- **Причина отклонения**: Размывает ответственность конечного автомата синхронизации и усложняет демона логикой, относящейся исключительно к первичному мастеру настройки.

## 4. Спецификация компонентов

### 4.1. Абстракция выбора каталога (`ui`)

В `dev.mimir.ui.picker`:
```kotlin
interface PlatformFolderPicker {
    /**
     * Открывает диалог выбора папки.
     * Возвращает выбранный путь либо null при отмене (не изменяя текущий путь).
     * [initialPath] используется как начальная директория при открытии диалога (fallback: домашняя папка пользователя).
     */
    suspend fun pickDirectory(initialPath: String? = null): String?
}

val LocalFolderPicker = staticCompositionLocalOf<PlatformFolderPicker?> { null }
```

В `app-desktop` (`dev.mimir.desktop.picker.AwtFolderPicker`):
- Запускает `JFileChooser` на `Dispatchers.IO` через `EventQueue.invokeAndWait` (или `suspendCancellableCoroutine`).
- Устанавливает `fileSelectionMode = JFileChooser.DIRECTORIES_ONLY`.
- При `JFileChooser.APPROVE_OPTION` возвращает `selectedFile.absolutePath`. При `CANCEL_OPTION` или закрытии окна возвращает `null`.

### 4.2. Контракт API демона и модели (`daemon`, `MimirUiModel`)

1. **Конфигурация папки на Шаге 1 (`POST /api/v1/vault`)**:
   - Тело запроса: `{"vaultPath": "/path/to/vault"}`
   - Ответ: `{"vaultPath": "/path/to/vault", "fileCount": 142}`
   - `MimirUiModel.configureVault(path: String): Int` — возвращает количество найденных локальных файлов.

2. **Инспекция состояния хранилищ на Шаге 4 (`GET /api/v1/vault/inspect`)**:
   - Доступен после разблокировки хранилища.
   - Ответ:
     ```json
     {
       "localFileCount": 142,
       "remoteFileCount": 185,
       "requiresStrategyConfirmation": true
     }
     ```
   - Метод в `MimirUiModel`:
     ```kotlin
     data class VaultInspection(
         val localFileCount: Int,
         val remoteFileCount: Int,
         val requiresStrategyConfirmation: Boolean,
     )
     suspend fun inspectVault(): VaultInspection
     ```

### 4.3. Мастер первого запуска (`SetupWizardScreen.kt`)

Состояния мастера:
1. `Step.Vault`:
   - Текстовое поле ввода пути к папке.
   - Кнопка «📁 Обзор…» (активна при наличии `LocalFolderPicker`). При выборе путь подставляется в поле и сразу отправляется в `model.configureVault(path)`.
   - Индикатор: `✓ Найдено заметок: 142` (или сообщение об ошибке, если директория не существует).
2. `Step.Google`:
   - Авторизация через браузер (PKCE) или резервный Device Code.
3. `Step.Password`:
   - Ввод и проверка мастер-пароля шифрования (`model.unlock(...)`).
4. `Step.InitialResolution`:
   - Вызывается метод `model.inspectVault()`.
   - Если `requiresStrategyConfirmation == true` (файлы есть и локально, и в Drive):
     - Отображается информационная карточка: «Обнаружено существующее хранилище в Google Drive (185 файлов) и локальные заметки (142 файла)».
     - Карточка утвержденной стратегии: **«Двустороннее слияние с защитой от потерь»** (скачает недостающие файлы из Drive, загрузит новые локальные заметки; при конфликтах создаст копии `(conflict-...)`).
     - Кнопка: **«Завершить настройку и синхронизировать»** $\rightarrow$ переход к главному экрану и вызов `model.triggerSync()`.
   - Если `requiresStrategyConfirmation == false` (одна из сторон пустая), мастер завершается сразу без промежуточных вопросов.

### 4.4. Дизайн-система Obsidian (`MimirTheme.kt`)

Тема поддерживает переключение день/ночь в зависимости от `isSystemInDarkTheme()`.

#### Obsidian Dark Tokens
- **Background**: `#1e1e1e`
- **Surface**: `#252525`
- **SurfaceVariant**: `#2e2e2e`
- **Border / Outline**: `#363636`
- **Primary Accent**: `#705dcf`
- **Primary Hover**: `#7c3aed`
- **OnSurface (Text)**: `#dcddde` / `#f5f5f5`
- **OnSurfaceMuted**: `#8a8a8a`

#### Obsidian Light Tokens
- **Background**: `#ffffff`
- **Surface**: `#f6f6f6`
- **SurfaceVariant**: `#eeeeee`
- **Border / Outline**: `#d4d4d4`
- **Primary Accent**: `#705dcf`
- **Primary Hover**: `#604bc5`
- **OnSurface (Text)**: `#2e2e2e` / `#181818`
- **OnSurfaceMuted**: `#757575`

#### Формы и компоненты
- **Скругления (`Shapes`)**: `extraSmall = 4.dp`, `small = 6.dp`, `medium = 8.dp`.
- **Кнопки**: Компактные кнопки высотой 32–36 dp со скруглением 4 dp и тонкими бордерами.
- **Поля ввода**: Фон `#141414` (Dark) / `#f0f0f0` (Light), тонкий бордер 1 dp, акцентная подсветка `#705dcf` при фокусе.

## 5. План тестирования и верификации

1. **Unit-тесты UI (`SetupWizardScreenTest.kt`)**:
   - Проверка вызова `PlatformFolderPicker` при клике на «Обзор…» и обновления поля ввода.
   - Проверка перехода на шаг `Step.InitialResolution`, если `requiresStrategyConfirmation = true`.
   - Проверка пропуска шага `Step.InitialResolution`, если `requiresStrategyConfirmation = false`.
2. **Интеграционные тесты демона (`InspectVaultTest.kt`, `ConfigureVaultTest.kt`)**:
   - `POST /api/v1/vault` возвращает валидное число файлов.
   - `GET /api/v1/vault/inspect` возвращает корректные счетчики после `unlock`.
3. **Визуальная верификация**:
   - Проверка контрастности и стилей Obsidian в темной и светлой темах.
   - Проверка неблокирующего открытия `JFileChooser` на Desktop.
