# Mimir — этап 1: шифрование, совместимое с rclone crypt

Дата: 2026-10-23
Статус: на согласование
Родительская спека: `2026-10-23-mimir-design.md` (раздел 6.3). При конфликте права родительская спека.

## 1. Контекст и порядок этапов

Реальная начинка делается тремя независимыми циклами «спека → план → выполнение»:

1. **Шифрование (этот документ).** Нет внешних зависимостей (сеть, секреты, Google); эталон — установленный rclone; от формата зависят движок, Drive, расширение и web UI.
2. Движок синхронизации — на `InMemoryRemoteStorage` с настоящим шифром, без OAuth.
3. OAuth и `GoogleDriveStorage` — последним (нужен проект Google Cloud, часть проверок ручная).

## 2. Цель и критерии успеха

Заменить `NotImplementedCipher` реализацией `RcloneCipher`, формат которой **бит-в-бит совместим с rclone crypt**:

- файл, зашифрованный Mimir, расшифровывается rclone, и наоборот;
- имена сегментов (режим `filename_encryption = standard`, `directory_name_encryption = true`, `filename_encoding = base32`) совпадают с rclone;
- один и тот же код работает на jvm, android, js, wasmJs;
- сборка и тесты проходят без секретов, сети и rclone.

## 3. Не цели этапа

Хранение пароля в `SecretStore`, UI ввода пароля, подключение шифра к движку, режимы `obfuscate`/`off`, `base64`/`base32768`-кодировки имён, обфускация пароля в формате rclone-конфига (в `RcloneCipher` передаётся пароль в открытом виде).

## 4. Формат (то, что обязана воспроизвести реализация)

### 4.1 Ключи
`scrypt(password, salt, N=16384, r=8, p=1, dkLen=80)`. Соль — `password2` (UTF-8), если задан и непуст, иначе стандартная соль rclone `A8 0D F4 3A 8F BD 03 08 A7 CA B8 3E 58 1F 86 B1`. Пустой пароль не допускается (`IllegalArgumentException`): rclone тоже не принимает его в конфиге. Результат: `dataKey` = байты 0..31, `nameKey` = 32..63, `nameTweak` = 64..79.

### 4.2 Содержимое файла
`"RCLONE\x00\x00"` (8 байт) + nonce (24 байта, случайный) + блоки. Блок: до 65536 байт открытого текста → NaCl `secretbox` (XSalsa20-Poly1305), т. е. 16 байт тега + данные. Nonce блока n = исходный nonce + n как 192-битное little-endian число (перенос между байтами). Пустой файл — только заголовок (32 байта). Неполный или с неверным тегом блок, неверная магия — ошибка расшифровки (`CryptException`, не тихий мусор).

### 4.3 Имена
Для каждого сегмента пути отдельно: UTF-8 → дополнение PKCS#7 до кратности 16 → EME (Halevi–Rogaway) на AES-256 с ключом `nameKey` и tweak `nameTweak` → base32 (алфавит `0-9a-v`, нижний регистр, без `=`). Пустой сегмент остаётся пустым. Расшифровка обратна; невалидный base32, длина не кратная 16 или неверное дополнение — `CryptException`.

## 5. Дизайн

Всё в `core/commonMain`, пакет `dev.mimir.core` (как существующий `Cipher`); отдельные примитивы в подпакете `dev.mimir.core.crypto`.

| Единица | Назначение | Зависит от |
|---|---|---|
| `Sha256`/`HmacSha256`/`Pbkdf2` | KDF-основа | — |
| `Scrypt` | `scrypt(pw, salt, N, r, p, dkLen)` | Pbkdf2, Salsa20/8 core |
| `XSalsa20`, `Poly1305`, `SecretBox` | NaCl `secretbox` seal/open | — |
| `Aes256` (только блочное шифрование/расшифровка одного блока) | основа EME | — |
| `Eme` | широкоблочное шифрование имён | Aes256 |
| `Base32Hex` | кодирование имён | — |
| `RcloneCipher(password, password2 = null) : Cipher` | собирает всё; `encryptName`/`decryptName`, потоковые `encrypt`/`decrypt` | всё выше |
| `CryptException` | ошибка формата/подлинности | — |

Решения:
- **Чистый Kotlin, без внешних крипто-библиотек.** Библиотеки с таргетами js/wasmJs не дают scrypt, XSalsa20-Poly1305 и EME одновременно, а расширению и web UI нужен тот же код (родительская спека 6.3). *Ruling этапа.* Риск закрывается разделом 6.
- **Потоковость:** `encrypt`/`decrypt` возвращают `Source`, который читает исходный `Source` по одному блоку (64 КиБ) и не загружает файл целиком.
- **Источник случайности для nonce:** внедряется в конструктор (`nonceSource: () -> ByteArray`), по умолчанию — платформенный CSPRNG через `expect/actual` (jvm/android: `SecureRandom`; js/wasmJs: `crypto.getRandomValues`). В тестах — детерминированный.
- Результат scrypt (~100 мс на jvm, дольше на js) считается один раз в конструкторе; ключи не логируются, `toString()` их не раскрывает.
- Публичный API `Cipher` не меняется. Интерфейс остаётся синхронным; `NotImplementedCipher` удаляется. Пароля в скелете нигде нет, поэтому места, где он использовался как заглушка (план уточнит их `grep`ом), получают явную заглушку «нет пароля» до этапа 2; `RcloneCipher` создаётся только из пароля.

## 6. Тестирование (TDD, `commonTest`)

1. **Стандартные векторы:** SHA-256/HMAC/PBKDF2-HMAC-SHA256 (RFC 6070-стиль и RFC 7914), scrypt (RFC 7914 §12), Salsa20/XSalsa20 и secretbox (векторы NaCl), Poly1305 (RFC 8439), AES-256 (FIPS-197), EME (векторы из reference-реализации).
2. **Golden-векторы rclone:** скрипт `scripts/gen-rclone-vectors.sh` (rclone ≥ 1.60) один раз создаёт: несколько имён (ASCII, кириллица, пробелы, длинное), файлы размером 0, 1, 65535, 65536, 65537, 200000 байт, для двух конфигураций (`password` только; `password`+`password2`). Результат (`core/src/commonTest/resources/rclone-vectors/`) коммитится; обычные тесты rclone не запускают. Тесты проверяют и расшифровку эталона нашим кодом, и побайтное совпадение нашего шифрования с эталонным при фиксированном nonce.
3. **Свойства:** round-trip для случайных размеров вокруг границ блока; порча одного байта (заголовок, тег, тело) → `CryptException`; обрезка файла на границе блока → `CryptException`; сегменты с unicode и длиной > 143 байт шифртекста не теряются.
4. **Интеграционный тест (jvm, опциональный):** если `rclone` найден в PATH, наш шифртекст расшифровывается `rclone cryptdecode`/`rclone copy` из временного каталога; иначе тест пропускается с сообщением.
5. Таргеты: тесты `core` идут на jvm, js (`CHROME_BIN=/usr/bin/chromium`) и wasmJs (nodejs); производительность scrypt на js/wasm не должна приводить к таймауту (проверяется).

## 7. Ошибки и безопасность

- Все ошибки формата и аутентификации — `CryptException` с сообщением без секретов.
- Сравнение тега Poly1305 — за постоянное время.
- Пароль и производные ключи не попадают в логи и `toString()`.
- Оговорка (из родительской спеки): размеры и время изменения в Drive остаются видны, как у rclone crypt.

## 8. Объём работы и критерий готовности

1. Все примитивы и `RcloneCipher` реализованы, `NotImplementedCipher` удалён.
2. `mise run test` зелёный на jvm/js/wasmJs, с и без Android SDK, без rclone и без секретов.
3. Golden-векторы закоммичены; опциональный интеграционный тест проходит локально (rclone на машине есть).
4. `EncryptedRemoteStorage` + `RcloneCipher` + `InMemoryRemoteStorage` проходят round-trip-тест на путях вида `Здоровье/Анализы мамы.md`, а в хранилище лежат только шифрованные сегменты.
5. README: раздел о совместимости с rclone (параметры, как расшифровать vault вручную).
