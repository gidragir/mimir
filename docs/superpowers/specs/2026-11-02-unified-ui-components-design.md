# Mimir: Спецификация единой дизайн-системы и библиотеки веб-компонентов (`@mimir/ui-web`)

**Дата:** 2026-11-02  
**Статус:** Proposal  
**Область:** `web-ui`, `browser-extension`, `obsidian-plugin`, общая дизайн-система UI

---

## 1. Назначение и контекст (Intent & Why)

Перед полномасштабной разработкой `web-ui` (веб-интерфейса, раздаваемого демоном Mimir в headless/Docker и браузере) требуется создать единую систему UI-компонентов и дизайн-токенов.

На данный момент:
- `app-desktop` и `app-android` используют Kotlin Compose Multiplatform (`:ui`) с темой `MimirTheme` (`ObsidianDarkColors`, `ObsidianLightColors`) и стилем `ObsidianStyle`.
- `browser-extension` использует самописную верстку на Kotlin/JS с манипуляциями DOM (`PopupDomView.kt`) и статическим CSS (`popup.css`).
- `web-ui` содержит только заготовку Wasm Compose, которая громоздка для веба и не переиспользуется в других веб-клиентах.

Цель спецификации — утвердить архитектуру общей дизайн-системы и пакета компонентов `@mimir/ui-web` на TypeScript/TSX, который обеспечит 100% консистентный UX и визуальную идентичность стиля Obsidian/Google Drive во всех веб-интерфейсах Mimir, сохраняя строгое соответствие с нативным Compose.

---

## 2. Цели, не-цели, анти-цели

### Цели
1. **Дизайн-система токенов (Design Tokens as Single Source of Truth):**
   - Формализовать токены цветов, отступов, радиусов, типографики и состояний.
   - Токены на вебе экспортируются как CSS-переменные (`--mimir-*`) и TypeScript-типы, а в Kotlin Compose зеркалируются через `MimirTheme` и `ObsidianStyle`.
2. **Пакет `@mimir/ui-web` на TypeScript/TSX:**
   - Создать переиспользуемый пакет в pnpm-монорепозитории (`packages/ui-web` или `ui-web/`).
   - Реализовать чистые презентационные компоненты (Dumb/Presentational Components) по паттерну UDF (Unidirectional Data Flow): компоненты получают строго типизированный State и передают события через Callbacks.
3. **Расширяемость под будущие адаптеры хранилищ (Storage Provider Strategy):**
   - Проектирование экранов настройки и авторизации с использованием паттернов Стратегия (Strategy) и Реестр (Registry).
   - Интерфейс не завязан жестко на один Google Drive: компоненты провайдеров (`StorageProviderDescriptor`, `AuthProviderForm`) поддерживают как OAuth/Device Code (Google Drive, OneDrive), так и формы учетных данных (WebDAV, Nextcloud, S3).
4. **Сквозная миграция UI существующего расширения (`browser-extension`):**
   - Полная замена устаревшего DOM-рендеринга (`PopupDomView.kt` и сырого `popup.css`) на презентационные TSX-компоненты из `@mimir/ui-web`.
   - Интероп через чистые контракты состояния (`ExtensionUiState` транслируется в свойства компонентов).
5. **Подготовка базы для `web-ui`:**
   - Подготовка легковесного SPA-каркаса `web-ui` на базе `@mimir/ui-web`, готового к подключению к HTTP API демона Mimir.
6. **Режим Operate (по стандарту `impeccable`):**
   - Утилитарный, лаконичный и функциональный интерфейс (эстетика Obsidian + надежность Google Drive).
   - Поддержка темной (`#1E1E1E`) и светлой (`#FFFFFF`) тем с фирменным акцентом Obsidian (`#705DCF`).
7. **Все обязательные состояния интерфейса (по регламенту `mimir-ui-ux`):**
   - Загрузка (скелетон / спиннер), Пустое состояние (пояснение + действие), Ошибка (человеческий текст + кнопка «Повторить»), Офлайн, Прогресс долгой операции (`SyncProgress`), Успех, Подтверждение разрушительного действия.
8. **Адаптивность и доступность:**
   - Поддержка трех сценариев размера: узкий Chrome Popup (320–400 px), SidePanel / мобильный экран (360–640 px), десктопное окно Web UI / Full-tab с двухколоночным сплитом (≥ 768 px).
   - Контрастность текста ≥ 4.5:1, доступность с клавиатуры (Tab, Enter, Esc), семантические HTML-теги и ARIA-атрибуты.

### Не-цели
- Переписывание десктопного (`app-desktop`) и Android (`app-android`) интерфейсов на веб-технологии. Они остаются на нативном Compose Multiplatform.
- Реализация сетевого/криптографического рантайма внутри пакета UI-компонентов. Пакет UI-компонентов занимается исключительно рендерингом и интеракциями.
- Редактор Markdown (на данном этапе поддерживается только чтение и переключение исходника/рендеринга).

### Анти-цели
- Использование тяжеловесных сторонних UI-библиотек (MUI, Ant Design и т.д.), приводящих к раздуванию бандла свыше 50 КБ.
- Вшивание произвольных `hex`-цветов и отступов «на глаз» вне системы токенов.
- Вывод технических терминов («хэш», «индекс», «ревизия», сырые стек-трейсы исключений) в интерфейс.
- Хардкод единственного облачного провайдера (Google Drive) в разметке компонентов без возможности расширения.

## 3. Рассмотренные подходы (Approaches)

### Вариант 1. Двухуровневая архитектура: Token-First + TS/TSX библиотека `@mimir/ui-web` (Выбран)
- **Суть:** 
  - Единый набор дизайн-токенов фиксирует эстетику.
  - Веб-клиенты (`web-ui`, `browser-extension`, `obsidian-plugin`) используют общую легковесную библиотеку компонентов на TSX (Preact/React + Tailwind/CSS Variables).
  - Нативные клиенты (`app-desktop`, `app-android`) используют Compose Multiplatform, визуально синхронизированный по тем же токенам.
- **Плюсы:**
  - Легковесный веб-бандл (минимальный оверхед, мгновенный запуск в Chrome Extension и браузере).
  - Быстрая разработка интерфейсов на современной экосистеме TS/TSX.
  - Сохранение нативной скорости и стабильности Compose на Desktop и Android.
- **Минусы:**
  - Поддержка двух реализаций компонентов (Compose и TSX), синхронизируемых через спецификацию токенов и экранов.

### Вариант 2. Единый Compose Wasm для всех веб-интерфейсов (Отклонён)
- **Суть:** Компиляция существующего `:ui` в WebAssembly для `web-ui`.
- **Причина отклонения:** Бандл размером 15–25 МБ, рендеринг через Canvas/WebGL (проблемы с четкостью шрифтов и доступностью), несовместимость с Chrome Extension Popup (жесткие требования к cold start и ограничения CSP) и Obsidian.

### Вариант 3. Полный перенос Desktop на Web-оболочку (Tauri/Electron) (Отклонён)
- **Суть:** Отказ от Compose Desktop в пользу единого веб-приложения везде.
- **Причина отклонения:** Ломает существующую кодовую базу Mimir, ухудшает интеграцию с Linux (niri/Wayland/AWT launcher), требует радикальной переделки packaging (Arch PKGBUILD, MSI).

## 4. Инварианты Mimir

### 4.1 Платформы
| Платформа | Роль компонента | Поведение / Ограничения |
| :--- | :--- | :--- |
| **`web-ui`** | Основной потребитель `@mimir/ui-web` | SPA-приложение, открывается в браузере с бэкендом демона. Поддерживает адаптивную верстку (мобильный вид и сплит-панель). |
| **`browser-extension`** | Потребитель `@mimir/ui-web` | Работает в SidePanel, Popup и Tab-режиме (`popup.html?mode=tab`). Критичен минимальный размер бандла и отсутствие eval/unsafe inline скриптов. |
| **`obsidian-plugin`** | Потенциальный потребитель | Отображение статуса и модальных окон синхронизации в стиле Obsidian. |
| **`app-desktop` & `app-android`** | Зеркалирование спецификации | Используют `:ui` на Compose, визуально неотличимы от веб-версии за счет единых токенов `MimirTheme`. |

### 4.2 Дизайн (Паттерны и структура)
- **Design Tokens:** Цветовая палитра Obsidian, типографика, шкала отступов (4, 8, 12, 16, 24, 32 px), радиусы (4, 6, 8 px). Токены поддерживаются декларативно в CSS Variables и зеркалируются в Kotlin `MimirTheme`/`ObsidianStyle` без усложнения инфраструктуры тяжелыми генераторами (Style Dictionary).
- **UDF (Unidirectional Data Flow):** Каждый компонент — чистая функция от `props`. Никаких сайд-эффектов и скрытых сетевых запросов. Компоненты UI не знают о сетевых клиентах или хранилище.
- **Паттерны проектирования для расширяемости хранилищ (Storage Providers):**
  - **Strategy (Стратегия аутентификации):** UI авторизации абстрагирован от конкретного облачного сервиса через `StorageAuthStrategy`:
    - `OAuthRedirectStrategy` (Google Drive Desktop, OneDrive) — браузерный вход через URL и loopback.
    - `DeviceCodeStrategy` (Google Drive Device Flow, headless/CLI) — показ кода устройства и ссылки.
    - `CredentialsFormStrategy` (WebDAV, Nextcloud, S3) — ввод URL сервера, логина и пароля/App token.
  - **Registry (Реестр провайдеров):** Список доступных хранилищ передается в UI в виде дескрипторов `StorageProviderDescriptor(id, displayName, icon, authKind, fields)`. Добавление нового адаптера в ядро (`core`/`drive`) не требует изменения разметки экранов.
  - **Ports & Adapters (Гексагональная архитектура):** Пакет `@mimir/ui-web` выступает портом отображения. `browser-extension` и `web-ui` передают адаптеры событий (`onLogin`, `onSync`, `onOpenNote`, `onSelectVault`).
- **Markdown-рендеринг:** Встроенный легковесный парсер `SafeMarkdownViewer` без тяжелых внешних зависимостей (Zero-dependency, парсинг регулярными выражениями по аналогии с `SafeMarkdownRenderer.kt`, размер < 2 КБ, строгий CSP без `eval` и `unsafe-inline`).
- **Компонентная иерархия:**
  - *Atoms:* `Button`, `Input`, `PasswordInput`, `Badge`, `StatusBadge`, `Spinner`, `ProgressBar`, `Icon`, `Banner`.
  - *Molecules:* `Toolbar`, `Breadcrumbs`, `AccountRow`, `DeviceCodeBlock`, `StorageProviderSelector`, `CredentialsForm`, `EmptyState`, `ErrorState`.
  - *Organisms:* `FileTree` (навигация по заметкам), `MarkdownViewer` (безопасный рендеринг), `StatusPanel` (состояние демона, прогресс, ошибки), `ProviderAuthCard`.
  - *Templates / Screens:* `SetupWizardLayout`, `StatusScreenLayout`, `SplitWorkspaceLayout`.

### 4.3 IO
- Пакет `@mimir/ui-web` содержит **0 сетевых обращений** и **0 обращений к ФС/диску**.
- Нулевой runtime-оверхед: bundle size библиотеки в сжатом виде — не более **20 КБ gzip** (при использовании Preact).
- Асинхронные операции инициируются контейнерами приложений (`web-ui`, `browser-extension`) через клиентские сервисы.

### 4.4 UX
- **Режим:** Operate (высокая сканируемость, лаконичность, отсутствие декоративного визуального шума).
- **Все состояния экрана:**
  1. *Loading:* Скелетон или центрированный спиннер с подписью текущей операции.
  2. *Empty:* Четкое сообщение о пустом хранилище/папке и одна главная кнопка действия.
  3. *Error:* Человеческое описание проблемы («Нет доступа к Google Drive») + кнопка («Войти снова»). Запрещены сырые исключения.
  4. *Offline:* Индикатор «Офлайн: изменения сохранены, синхронизация продолжится при появлении сети».
  5. *InProgress:* Блокировка кнопок от повторных нажатий, анимированный прогресс-бар (`SyncProgress`).
  6. *Success:* Ненавязчивое подтверждение (галочка, смена статуса бейджа), без всплывающих alert/modal окон.
  7. *Destructive:* Явное подтверждение опасных операций (например, сброс авторизации).
- **Тексты:** Строго по-русски, из централизованного словаря `SyncTextsWeb` (без «хэш», «индекс», «ревизия»). До подключения статус строго: `Mimir: not connected`.

### Геометрия и сетка
- **Отступы (Spacing):**
  - `none`: 0
  - `xs`: 4px (внутренние микро-отступы, бейджи)
  - `sm`: 8px (отступы в строках, тулбарах)
  - `md`: 12px (стандартный gap в формах)
  - `lg`: 16px (внутренние отступы экранов и карточек)
  - `xl`: 24px (расстояние между секциями)
  - `2xl`: 32px (крупные отступы на десктопе)
- **Скругления (Border Radius):**
  - `xs`: 4px (бейджи, код)
  - `sm`: 6px (кнопки, поля ввода, элементы дерева)
  - `md`: 8px (карточки, модальные окна, панели)
- **Высота интерактивных элементов:**
  - Desktop compact: 32px (кнопки, инпуты тулбара)
  - Touch / Standard: 48px (кнопки на мобильных устройствах и основные CTA)

## 6. Каталог компонентов `@mimir/ui-web`

### 6.1 Атомы
1. **`Button`:**
   - Варианты: `primary` (заливка акцентом), `secondary` (бордер, нейтральный фон), `ghost` (без бордера, подсветка при ховере), `destructive` (красный акцент).
   - Размеры: `compact` (32px), `standard` (40px), `large` (48px).
   - Свойства: `disabled`, `loading` (спиннер вместо текста), `icon`, `onClick`.
2. **`Input` & `PasswordInput`:**
   - Поля ввода с поддержкой состояний `focused`, `error`, `disabled`.
   - `PasswordInput` содержит встроенную кнопку-переключатель видимости пароля (👁 / 🚫).
3. **`StatusBadge`:**
   - Отображение статуса демона/синхронизации:
     - `CONNECTED` (зеленая точка, «Подключено»)
     - `SYNCING` (вращающийся индикатор, «Синхронизация…»)
     - `OFFLINE` (серая точка, «Офлайн»)
     - `ERROR` (красная точка, «Ошибка»)
     - `NOT_CONNECTED` («Mimir: not connected»)
4. **`ProgressBar` & `Spinner`:**
   - Детерминированный прогресс (0–100%) для `SyncProgress` (счетчик файлов и байт) и индетерминированный спиннер.
5. **`Banner`:**
   - Информационная полоса (Info, Warning, Error) с возможностью закрытия или кнопкой действия.

### 6.2 Молекулы и Организмы
1. **`Toolbar`:**
   - Шапка с кнопкой «Назад» (в мобильном режиме), строкой поиска по заметкам, переключателем режима просмотра (📖 / 📝) и кнопкой настроек/статуса.
2. **`FileTree`:**
   - Иерархический список папок и заметок Markdown.
   - Поддержка раскрытия/сворачивания папок, подсветка активного файла, индикация статуса синхронизации файла (изменен, синхронизирован, конфликт).
3. **`MarkdownViewer`:**
   - Безопасный рендерер заметок с подсветкой заголовков, цитат, списков задач (`- [ ]`), кодовых блоков с кнопкой копирования, и переключением в сырой режим (моноширинный `<pre>`).
4. **`StatusCard`:**
   - Информационный блок текущего состояния: название хранилища, статус аккаунта Google, время последней синхронизации, кнопка ручного запуска «Синхронизировать сейчас».

### 6.3 Шаблоны экранов (Screen Layouts)
1. **`SetupWizardLayout`:**
   - Пошаговый мастер первоначальной настройки (Выбор хранилища → Подключение Google Drive → Пароль шифрования → Первичная синхронизация).
2. **`SplitWorkspaceLayout`:**
   - Двухколоночный интерфейс: слева дерево папок (280px), справа область ридера заметки (до 760px по центру). В экранах < 768px автоматически трансформируется в одноколоночный пошаговый режим.

## 7. Технический стек и организация кода

### 7.1 Пакетный менеджер и версионирование
- **Пакетный менеджер:** строго **`pnpm`** (актуальная стабильная версия pnpm workspace). Все зависимости устанавливаются и резолвятся только через `pnpm`.
- **Версии фреймворков и инструментов:** строго самые свежие стабильные релизы, доступные в реестре npm через pnpm на момент разработки:
  - TypeScript (последняя стабильная 5.x)
  - Preact (последняя стабильная 10.x)
  - Tailwind CSS (последняя стабильная v4.x с нативным CSS-based конфигом `@theme`)
  - Инструменты сборки и тестирования: Vite / tsup (актуальные релизы), Vitest (актуальный релиз), `@testing-library/preact`.

### 7.2 Пакет `@mimir/ui-web`
- **Расположение:** `packages/ui-web` (зарегистрирован в корневом `pnpm-workspace.yaml`).
- **Фреймворк:** **Preact** (с чистым JSX/TSX API). Обеспечивает минимальный размер бандла (~3.5 КБ) и мгновенный рендер в Chrome Extension Popup без накладных расходов React.
- **Стилизация:** CSS Custom Properties (дизайн-токены) + **Tailwind CSS v4** с компиляцией в один файл `dist/mimir-ui.css`.
- **Сборка:** `tsup` или `vite library mode` (выпуск ESM, CJS и `.d.ts` описаний типов).
- **Тестирование:** `vitest` + `@testing-library/preact` с тестами на каждое состояние каждого компонента.

### 7.3 Миграция клиентов
1. **`browser-extension`:**
   - Устаревший класс `PopupDomView.kt` и файл `popup.css` заменяются монтированием Preact-компонента в контейнер `#app`.
   - Контроллер `ExtensionController.kt` передает состояние через подписку (`stateFlow`/listener), а Preact-приложение рендерит `SplitWorkspaceLayout` или пошаговый мастер настройки.
   - Сборка расширения интегрирует скомпилированные компоненты и стили `@mimir/ui-web/dist/mimir-ui.css`.
2. **`web-ui`:**
   - Каркас SPA-приложения на Preact, использующий шаблоны и компоненты из `@mimir/ui-web`.
