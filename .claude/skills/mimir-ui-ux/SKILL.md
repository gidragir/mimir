# UI/UX Mimir

## Суть

Ощущение — как у Google Drive для компьютера в оформлении Obsidian: указал папку и пароль, дальше всё видно и понятно без знания rclone/git. Экран считается готовым, когда у него продуманы **все состояния**, он выглядит современно в обеих темах и на всех размерах, и это проверено глазами.

## До кода: сценарий

В спеке/плане пункт **«UX»**: путь пользователя по шагам (что видит → что делает → что получает), для каждого экрана — таблица состояний ниже и что из неё неприменимо. Ориентиры: Material 3, Obsidian, Google Drive for desktop, 1Password (онбординг).

## Обязательные состояния экрана

| Состояние | Что показать |
|---|---|
| Загрузка | индикатор/скелет на месте контента, не пустой экран; дольше ~1 с — что именно происходит |
| Пусто | пояснение и одно главное действие |
| Ошибка | что случилось и что делать, кнопка действия (повторить, войти снова); текст — из `*Texts` по типу ошибки, `e.message` и имена исключений в интерфейс не попадают |
| Нет сети | `Offline`: изменения сохранены, продолжится само |
| Долгая операция | прогресс (`SyncProgress`), отмена или «можно закрыть окно» |
| Действие в процессе | кнопка заблокирована, повторное нажатие не отправляет второй запрос |
| Успех | подтверждение на месте (строка, галочка), не модальное окно |
| Разрушительное действие | подтверждение с последствиями или отмена после |

## Оформление

- Цвета, формы, типографика — только из `MimirTheme`/`MaterialTheme` и помощников `ObsidianStyle`. Никаких `Color(0x…)` на экранах; новый токен — в теме для **обеих** тем.
- Отступы по шкале 4/8/12/16/24 dp; формы — ширина контента до ~640 dp по центру; иерархия: один заголовок, одно основное действие (filled), остальные — outlined/text.
- Размеры: окно desktop от 720×520 и больше, телефон ~360 dp; переполнение — прокрутка, не обрезка. Цели нажатия на касание ≥ 48 dp (компактные 32 dp — только desktop).
- Доступность: `contentDescription` у иконок, контраст текста ≥ 4.5:1, смысл не только цветом; клавиатура — Tab по порядку, Enter отправляет, Esc закрывает диалог, фокус на первом поле.
- Платформенные привычки — через сервисы из `mimir-cross-platform`: системный выбор папки, системный браузер для входа, трей/уведомления платформы, кнопка «Назад» на Android.

## Тексты

- Все строки экрана — в объекте `*Texts` (как `SyncTexts`), по-русски, человеческим языком: без «индекс», «хэш», «ревизия», «токен», «diff».
- Ошибка = что произошло + что сделать. Статус до подключения — ровно `Mimir: not connected`.

## Реализация и проверка

- Экран получает только `MimirUiModel` (UDF, см. `mimir-design-patterns`); вызовы модели — в корутине со своим состоянием «в процессе», UI-поток не блокируется.
- Тесты состояний — в `ui/src/desktopTest` на `FakeMimirUiModel`: каждое состояние таблицы имеет тест.
- Визуальная проверка обязательна: запустить приложение (скилл `run`), снять скриншоты в светлой и тёмной теме и при минимальном размере окна, приложить к отчёту, перечислить замеченные недостатки.

## Красные флаги

- Экран из одного «счастливого» состояния; пустое окно во время загрузки.
- `Color(0x…)`, разные отступы «на глаз», три одинаково выделенные кнопки.
- `e.message` или текст исключения в интерфейсе (в том числе подставленный в шаблон); техническая лексика.
- «Тесты прошли» без скриншота.
