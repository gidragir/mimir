# UI/UX Mimir

## Суть

Ощущение — как у Google Drive для компьютера в оформлении Obsidian: указал папку и пароль, дальше всё видно и понятно без знания rclone/git. Экран считается готовым, когда у него продуманы **все состояния**, он выглядит современно в обеих темах и на всех размерах, и это проверено глазами.

## До кода: сценарий

В спеке/плане пункт **«UX»**: путь пользователя по шагам (что видит → что делает → что получает), для каждого экрана — таблица состояний ниже и что из неё неприменимо. Ориентиры: Material 3, Obsidian, Google Drive for desktop, 1Password (онбординг).

## Обязательные состояния экрана

| Состояние | Что показать |
|---|---|
| Загрузка | индикатор/скелет на месте контента, не пустой экран; дольше ~1 с — что именно происходит |
| Пусто | пояснение и одно главное действие |
| Ошибка | что случилось и что делать, кнопка действия (повторить, войти снова); текст — из `*Texts` по типу ошибки, `e.message` и имена исключений в интерфейс не попадают |
| Нет сети | `Offline`: изменения сохранены, продолжится само |
| Долгая операция | прогресс (`SyncProgress`), отмена или «можно закрыть окно» |
| Действие в процессе | кнопка заблокирована, повторное нажатие не отправляет второй запрос |
| Успех | подтверждение на месте (строка, галочка), не модальное окно |
| Разрушительное действие | подтверждение с последствиями или отмена после |

## Оформление и дизайн-система

- **Single Source of Truth дизайн-токенов:** `design/tokens.json` определяет визуальный язык (палитра Obsidian, радиусы 4/6/8, шкала отступов 4/8/12/16/24/32 px).
- **Генерация и проверка рассинхронизации:** генератор `scripts/generate-tokens.mjs` транслирует токены в Kotlin Compose (`dev.mimir.ui.MimirTokens`) и веб (`tokens.css`). Проверка дрейфа обязательна: `pnpm run tokens:check` (или `node scripts/generate-tokens.mjs --check`).
- **Фирменные компоненты (`dev.mimir.ui.components.*`):** на экранах используются крафтовые компоненты вместо сырых Material 3 примитивов:
  - `MimirButton` (варианты `Primary`, `Secondary`, `Ghost`, `Danger`, состояния `loading`, `enabled`, компактный размер 32 dp / touch 48 dp).
  - `MimirTextField` (инсет-фон, скругление 6 dp, переключатель пароля с `contentDescription`, валидация и вывод ошибки).
  - `MimirCard` (контейнер с обводкой и фоном поверхности Obsidian).
  - `MimirStatusBadge` (светящаяся точка статуса + канонический `SyncStatus.label()`).
  - `MimirProgressBar` (детерминированный прогресс 0..1 и неопределенный режим, акцентный цвет).
- Цвета, формы, типографика — только из `MimirTokens`, `MimirTheme` и помощников `ObsidianStyle`. Никаких `Color(0x…)` на экранах; новый токен — в `design/tokens.json` для **обеих** тем с последующим `pnpm run tokens:generate`.
- **Геометрия полей и кнопок:** элементы в одной горизонтальной строке (поле ввода + кнопка действия) обязаны иметь одинаковую высоту (строго 56 dp для стандартных полей ввода, 44/32 dp для компактных). Использование `label` внутри `OutlinedTextField` в строках с кнопками запрещено (вызывает асимметрию и ступеньку ~8 dp) — использовать `placeholder` внутри и заголовок над полем.
- **Векторные иконки вместо emoji:** категорически запрещено использовать emoji (`📁`, `👁`, `🙈`) в кнопках и индикаторах. Использовать строго векторные иконки из `dev.mimir.ui.components.MimirIcons` (Lucide-стиль, 18-20 dp).
- **Определение темы:** в стилях и вспомогательных компонентах (`ObsidianStyle`) запрещено вызывать `isSystemInDarkTheme()` (игнорирует локальную тему родителя). Проверять тему через `MaterialTheme.colorScheme.surface == MimirTokens.DarkSurface`.
- **Десктопное окно и системный трей (Obsidian CSD):** Запрещено оставлять стандартный светлый заголовок ОС (`undecorated = false` на Windows), контрастирующий с тёмной темой Mimir, и архаичные серые меню AWT (`java.awt.PopupMenu`). Окно приложения обязано использовать бесшовный заголовок (`MimirTitleBar` на Compose с `WindowDraggableArea` и стилизованными кнопками в цветах `MimirTokens.DarkSurface`), а системный трей — интерактивный плавающий Compose-поповер со статусом хранилища, карточкой vault и прогрессом.
- Отступы по шкале `MimirTokens.Space*` (4/8/12/16/24/32 dp); формы — ширина контента до ~640 dp по центру; иерархия: один заголовок, одно основное действие (`Primary`), остальные — `Secondary`/`Ghost`.
- Размеры: окно desktop от 720×520 и больше, телефон ~360 dp; в браузерном расширении popup — от 320 px (без горизонтального скролла). Переполнение — прокрутка, не обрезка. Цели нажатия на касание ≥ 48 dp (компактные 32 dp — только desktop/web).
- Доступность: `contentDescription` у иконок и переключателей паролей, контраст текста ≥ 4.5:1, смысл не только цветом; клавиатура — Tab по порядку, Enter отправляет, Esc закрывает диалог, фокус на первом поле.
- Платформенные привычки — через сервисы из `mimir-cross-platform`: системный выбор папки, системный браузер для входа, трей/уведомления платформы, кнопка «Назад» на Android.

## Тексты

- Все строки экрана — в объекте `*Texts` (как `SyncTexts`), по-русски, человеческим языком: без «индекс», «хэш», «ревизия», «токен», «diff».
- Ошибка = что произошло + что сделать. Статус до подключения — ровно `Mimir: not connected`.

## Реализация и проверка

- Экран получает только `MimirUiModel` (UDF, см. `mimir-design-patterns`); вызовы модели — в корутине со своим состоянием «в процессе», UI-поток не блокируется.
- Тесты состояний — в `ui/src/desktopTest` на `FakeMimirUiModel`: каждое состояние таблицы имеет тест.
- Автоматизированная скриншотная верификация обязательна (скилл `mimir-ui-test`): `mise run screenshots` генерирует снимки экранов десктопа и веб-расширения для светлой и тёмной тем без запуска графического окружения.

## Красные флаги

- Экран из одного «счастливого» состояния; пустое окно во время загрузки.
- `Color(0x…)`, разные отступы «на глаз», три одинаково выделенные кнопки.
- Emoji в качестве иконок в кнопках и контролах.
- Разная высота поля ввода и соседней кнопки в одной строке.
- `e.message` или текст исключения в интерфейсе (в том числе подставленный в шаблон); техническая лексика.
- «Тесты прошли» без скриншотной верификации (`mise run screenshots`).
- Окно десктопа со стандартным белым тайтлбаром ОС поверх тёмной темы.
- Использование устаревшего `java.awt.PopupMenu` вместо стилизованного Compose-поповера.
